## 1. 導入

### 1.1 必要なもの

- Windows 版 Excel（Microsoft 365 / Excel 2016 以降を想定。動作を確かめたのは Microsoft 365 版のみ）
- マクロを含むブック（.xlsm）を開ける設定

### 1.2 配置

1. `sales_report_tool.xlsm` と `sample_data` フォルダを、同じフォルダに置きます。
2. インターネットから入手したファイルは、エクスプローラーで .xlsm を右クリック →［プロパティ］→「許可する」にチェックを入れて［OK］を押します（マクロがブロックされるのを解除するため）。
3. ブックを開き、上部に表示される［コンテンツの有効化］を押します。

### 1.3 動作確認

1. 「設定」シートの［レポート作成］ボタンを押します。
2. 「レポートを作成しました。取込明細：97 件」と表示され、`output` フォルダに PDF が作られれば導入完了です。

### 1.4 自社のデータで使う

1. 売上ファイルを置くフォルダを作り、「設定」シートの「入力フォルダ」にそのフォルダを入力します（例：`C:\売上データ\2026年度`）。
2. 売上ファイルの1行目は「日付, 顧客名, 商品名, 数量, 単価, 金額」にそろえます。
3. CSV を Excel 以外のシステムから出力している場合は、文字コード（UTF-8 / Shift_JIS）を確認して「CSV文字コード」を合わせます。

## 2. 毎月の運用

| 手順 | 作業 | 確認すること |
|---|---|---|
| 1 | 入力フォルダに今月分のファイルを追加する | ファイル名に `~$` が付いていない（Excel で開いたままではない） |
| 2 | ［レポート作成］ボタンを押す | 完了メッセージの「エラー」件数 |
| 3 | エラーが1件以上なら「エラー一覧」シートを開く | ファイル名・行番号・理由 |
| 4 | 元のファイルを直して、もう一度ボタンを押す | エラー件数が 0 件になる |
| 5 | 出力フォルダの PDF を送付・保管する | 帳票の対象期間と作成日時 |

PDF のファイル名には作成日時が入るため、前回の PDF は上書きされずに残ります。

## 3. 困ったとき

詳しい対応は [06_障害対応手順書](06_障害対応手順書.md) を参照。

| 表示・症状 | 原因 | 対処 |
|---|---|---|
| 入力フォルダが見つかりません（ERR-002） | フォルダ名の誤り、フォルダの移動 | 「入力フォルダ」を確認する。C:\ から始まる形で入力すると確実 |
| 入力フォルダに CSV / Excel ファイルがありません（ERR-003） | フォルダが空、拡張子が対象外 | .csv / .xlsx / .xls を置く |
| ブックがクラウド上の場所にあるため、相対パスを使えません（ERR-001） | OneDrive 等の同期フォルダにブックがある | 入力・出力フォルダを C:\ から始まる形で入力する |
| 取り込める明細が1件もありませんでした（ERR-004） | 全ファイルの見出しが違う、文字コードの不一致 | エラー一覧の理由を見る。文字化けしている場合は「CSV文字コード」を切り替える |
| PDF を保存できませんでした（ERR-005） | 同名の PDF を開いている、書き込み権限が無い | PDF を閉じる、出力フォルダを変更する |
| 印刷設定を反映できませんでした（ERR-005） | 既定のプリンターが無い | Windows の設定で既定のプリンター（「Microsoft Print to PDF」でも可）を設定する |
| ボタンを押しても何も起きない | マクロが無効 | 1.2 の手順 2・3 を行う |

## 4. 保守

### 4.1 ソースの構成

- VBA のソースは `src/` に UTF-8 のテキストで置いています。.xlsm は `build/build.py` で `src/` から組み立てます（[ADR-0003](adr/0003-source-as-text-build-workbook.md)）。
- VBE の「ファイルのインポート」で手動で取り込む場合は、事前に Shift_JIS に変換してください（VBE は .bas を Shift_JIS として読むため）。

### 4.2 変更後の確認

```text
python3 build/build.py            # src/ から .xlsm を作り直す
python3 tests/run_tests.py        # 実機の Excel で TC-001〜TC-008, TC-010 を実行
python3 tests/run_tests.py --pdf  # PDF 出力（TC-009）も含める
python3 build/release.py          # 出力例入りの配布用ブックと画像を作り直す
python3 tools/check_docs_trace.py # 設計書のエラーIDと障害対応手順書の対応を検査（TC-011。Excel 不要）
```

- テストは WSL2 から Windows の Excel を操作します。Excel を画面で開いている間は、作業中のブックに影響しないよう実行を中止します。
- テストが起動した Excel だけを終了し、利用者が開いている Excel には触れません。

### 4.3 よくある変更

| 変更内容 | 修正箇所 |
|---|---|
| 設定シートの行を移動する | セルを移動するだけでよい（コードは名前付きセルで参照している） |
| 入力ファイルの列名を変える | `modImport` の `ExpectedHeader` |
| シート名を変える | `modUtil` の `SHEET_*` 定数と、ブックのシート名 |
| 消費税の端数処理を変える | `modReport` の `ROUNDDOWN` の数式 |

## 5. 運用管理

### 5.1 定期点検

本ツールは常駐や定期実行の仕組みを持たず、利用者が［レポート作成］を押したときだけ動く。毎日の点検は不要で、実行のたびと変更のときに次を確かめる。

| 時期 | 確認すること | 見る場所 |
|---|---|---|
| 毎月（実行のたび） | 「前回の実行結果」が `正常終了：` で始まる | 設定シート |
| 毎月（実行のたび） | エラー件数が 0 件。1 件以上なら理由を確かめてから送付する | 完了メッセージ・帳票の集計サマリー・エラー一覧シート |
| 毎月（実行のたび） | 対象期間・作成日時・取込明細件数が想定どおり | 帳票の集計サマリー |
| 毎月 | 入力フォルダに、同じ月のファイルの写しなど不要なファイルが無い（すべて集計の対象になるため） | 入力フォルダ |
| 毎月 | 出力フォルダの PDF の数。PDF は上書きされずに増えるため、保管期間と整理の時期は運用で決める項目とする | 出力フォルダ |
| 変更時（Excel の更新、パソコン・既定のプリンターの変更、ブックの差し替え） | `sample_data` で 1.3 の動作確認を行い、取込明細 97 件で正常終了し、PDF が作られる | 完了メッセージ・出力フォルダ |
| 変更時（売上ファイルの出力元の変更） | 1行目の見出しと文字コードが 1.4 のとおり。新しいファイルで実行してエラー件数が 0 件 | エラー一覧シート |

### 5.2 バックアップと戻し方

ツールは入力ファイルを書き換えず、ブックを自動で保存しない。帳票は入力ファイルからいつでも作り直せるため、次の3つを残しておけば元に戻せる。保存先・世代数・保管期間は運用で決める項目とする。

| 対象 | 内容 | 残す時期 |
|---|---|---|
| ブック（`sales_report_tool.xlsm`） | 設定シートの値（入力フォルダ・出力フォルダ・文字コード・税率・PDF 出力）を含む | 導入時と、設定を変えたとき |
| 入力フォルダの売上ファイル | 帳票の元データ | 毎月、ファイルを追加したとき |
| 出力フォルダの PDF | 送付・保管した帳票 | 送付したとき |

ブックを戻す手順：

1. Excel で開いているブックを閉じる。
2. 壊れた、または誤って変更したブックは、名前を変えて残す（原因を調べるため）。
3. バックアップのブックを、元の場所に元の名前で置く。
4. ブックを開いてマクロを有効にし（1.2）、設定シートの値が想定どおりか確かめる。
5. ［レポート作成］を押して帳票を作り直し、「前回の実行結果」が `正常終了：` で始まることを確かめる。

ブックのバックアップが無い場合は、保守担当者が `python3 build/build.py` で `src/` からブックを組み立て直す（4.2）。組み立て直したブックの設定シートは既定値（入力フォルダ `sample_data` など）になるため、手順 4 で設定を入れ直す。

入力ファイルや PDF を戻す場合は、バックアップから元のフォルダへ写す。PDF を作り直す場合は、その月の入力ファイルをそろえて［レポート作成］を実行する（ファイル名の作成日時は実行した日時になる）。

### 5.3 資格情報・鍵・トークンの更新

該当なし。本ツールはパスワード・API キー・トークンを使わず、外部のサービスにも接続しない。読み書きするのは設定シートで指定したフォルダのファイルだけで、共有フォルダへのアクセス権は Windows のアカウントの権限に従う（ツールは資格情報を保持しない）。

### 5.4 連絡体制

連絡手段と連絡先は運用で決める項目とする。

| 役割 | 担うこと | 次に連絡する相手と時機 |
|---|---|---|
| 利用者 | 毎月の実行、エラー一覧に従った入力ファイルの修正（障害対応手順書 4章の「対処」まで） | 対処しても直らないとき、ERR-900 が出たときに運用担当者へ。表示された文言・エラー番号・発生日時を伝える |
| 運用担当者 | 設定シート・入力フォルダ・出力フォルダの見直し、バックアップからの復旧（5.2）、障害の記録（障害対応手順書 6章） | VBA の修正、ブックの組み立て直し、入力ファイルの形式変更への対応が必要なときに保守担当者へ |
| 保守担当者 | 原因の調査、`src/` の修正とブックの組み立て直し、テストの実行（4.2） | 修正後に運用担当者へ、差し替えるブックと確認の結果を渡す |
