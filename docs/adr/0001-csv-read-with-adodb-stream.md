## 背景

入力 CSV は UTF-8 と Shift_JIS のどちらでも届く可能性がある。
また、Excel で CSV を直接開くと、`2026-04` が日付に、`001` が数値に自動で変換されるなど、元の値が変わってしまう。

## 選択肢

| 案 | 内容 | 評価 |
|---|---|---|
| A | `Workbooks.Open` で CSV を開く | 文字コードを指定できず、UTF-8（BOM なし）が文字化けする。値の自動変換も起きる |
| B | `QueryTables`（テキストファイルの取り込み）を使う | 文字コードと列の型を指定できるが、シート上に接続と範囲が残り、後始末が必要 |
| C | `Open ... For Input` で1行ずつ読む | Shift_JIS 以外の文字コードを扱えない |
| D | `ADODB.Stream` で文字コードを指定して全文を読み、自前で列に分ける | 文字コードを明示でき、値は文字列のまま受け取れる。シートに接続や範囲を残さない |

## 決定

案 D を採用する。文字コードは設定シートの「CSV文字コード」で指定する。
列の分割は、ダブルクォートで囲まれた値（中のカンマ・二重のクォート）に対応した自前の関数で行う。

## 理由・影響

- 値を文字列のまま受け取り、日付・数値への変換は入力チェックで明示的に行うため、変換の失敗を行単位のエラーとして報告できる
- セルの中に改行を含む CSV は対象外とした（要件定義書の対象外に記載）
- ADODB は Windows 標準の部品で、追加のインストールは不要
