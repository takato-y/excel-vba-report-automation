## 背景

.xlsm はバイナリを含む ZIP 形式で、Git では変更点を追えない。
また、手作業で VBE にコードを貼り付ける運用では、ブックとソースの食い違いが起きやすい。

## 選択肢

| 案 | 内容 | 評価 |
|---|---|---|
| A | .xlsm だけを管理する | 差分が見えず、レビューできない |
| B | .xlsm を手で編集し、都度 .bas を書き出す | 書き出し忘れでソースとブックがずれる |
| C | `src/` の .bas / .cls を正とし、スクリプトで空のブックに取り込んで .xlsm を作る | ソースとブックが常に一致する。作成手順も再現できる |

## 決定

案 C を採用する。`build/build.py` が `src/` のモジュールと、シートの初期レイアウトを作る `build/modSetup.bas` を新しいブックに取り込み、初期化後に `modSetup` を取り除いて保存する。

## 理由・影響

- ソースは GitHub で読めるよう UTF-8 で保管する。ブック作成時に Unicode のまま VBE へ渡すため文字化けしない
- VBE の「ファイルのインポート」で手動で取り込む場合は、Shift_JIS に変換してから取り込む必要がある（導入・運用手順に記載）
- 同じ仕組みで自動テスト（`tests/run_tests.py`）も実機の Excel 上で実行する
